INNER JOIN vs LEFT / RIGHT JOIN

한 줄 요약 — INNER는 짝이 맞는 행만 남기고, OUTER(LEFT/RIGHT)는 짝이 없어도 한쪽 행을 살려두고 반대편을 NULL로 채운다.

RIGHT JOIN은 사실 안 써도 된다. A LEFT JOIN B 와 B RIGHT JOIN A 는 완전히 같은 결과다. 테이블 순서만 바꾸면 되니, 실무에서는 방향을 헷갈리지 않으려고 LEFT JOIN 하나로 통일해서 쓰는 경우가 많다.
문제 7

재고가 한 번도 등록되지 않은 제품 → LEFT JOIN이 반드시 필요

-- 찾으려는 건 "stock에 짝이 없는" 제품 = INNER JOIN이 버리는 바로 그 행
SELECT 제품명
FROM product p LEFT JOIN stock s ON p.제품번호_pk = s.제품번호_fk
WHERE 재고수량 IS NULL;

여기서 INNER JOIN을 쓰면? 짝 없는 책상·스탠드 행이 조인 단계에서 이미 사라진다. 남은 4행에는 재고수량이 전부 값이 있으므로 IS NULL 조건에 걸리는 행이 하나도 없어 결과가 0건이 된다. "없는 것을 찾는 질문"에 INNER JOIN을 쓰면 구조적으로 답이 나올 수 없다.
OUTER JOIN이 만들어내는 NULL은 "값이 비어있다"가 아니라 "짝이 없었다"는 표시다. 그래서 LEFT JOIN + IS NULL 조합이 "~하지 않은 대상 찾기"의 정석 패턴이 된다.
문제 8

카테고리별 재고 합계 → 값이 있는 것만 집계하므로 INNER JOIN

SELECT 카테고리명, SUM(s.재고수량) AS 총재고
FROM pcategory p INNER JOIN product p2 ON p.카테고리번호_pk = p2.카테고리번호_fk
                INNER JOIN stock s   ON p2.제품번호_pk = s.제품번호_fk

어느 쪽이 정답인가? 문제가 "재고가 있는 카테고리의 합계"를 원하면 지금처럼 INNER JOIN이 맞다. 하지만 "각 카테고리별로"라는 표현을 재고 0인 카테고리까지 포함하라는 뜻으로 읽는다면 LEFT JOIN + IFNULL(SUM(s.재고수량), 0)로 써야 한다. (SUM(NULL)은 0이 아니라 NULL이므로 IFNULL/COALESCE가 필요하다.)

3. 가장 많이 틀리는 함정 — LEFT JOIN을 써놓고 INNER로 만들어버리기

-- ❌ LEFT JOIN인데 WHERE에 오른쪽 테이블 조건을 걸면...
FROM product p LEFT JOIN stock s ON p.제품번호_pk = s.제품번호_fk
WHERE s.재고수량 > 0        -- NULL > 0 은 참이 아님 → NULL 행이 전부 탈락 = INNER JOIN과 동일

-- ✅ 짝 없는 행을 살려두고 싶으면 조건을 ON 절로 옮긴다
FROM product p LEFT JOIN stock s ON p.제품번호_pk = s.제품번호_fk AND s.재고수량 > 0

ON은 조인할 때 짝을 맞추는 조건, WHERE는 조인이 끝난 뒤 결과를 걸러내는 조건이다. INNER JOIN에서는 둘의 결과가 같지만, OUTER JOIN에서는 완전히 달라진다. 문제 7의 WHERE 재고수량 IS NULL은 "NULL 행만 남기려는" 의도적 예외라 괜찮다.

4. 문제 보고 30초 안에 고르는 법

  • "~한 적 없는 / ~가 없는 / 미등록 / 한 번도 ~않은" → LEFT JOIN + WHERE 오른쪽컬럼 IS NULL · 문제 7이 여기 해당
  • "양쪽 모두에 존재하는 것만 / ~한 내역을 집계" → INNER JOIN · 문제 8이 여기 해당
  • "전체 목록을 다 보여주되, 없는 건 0이나 빈칸으로" → LEFT JOIN + IFNULL(...) / COALESCE(...)
  • 기준이 되는 테이블을 FROM 뒤에 먼저 쓴다 "제품 기준으로 재고를 붙인다" → FROM product LEFT JOIN stock. 이 순서만 지키면 RIGHT JOIN은 평생 쓸 일이 거의 없다.
